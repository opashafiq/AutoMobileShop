User enters credentials → auth.login() runs → token stored → fetchUserSession(username, token) runs → user saved to localStorage
Page redirects to dashboard → UserProvider rehydrates from localStorage → useUser() returns user object

Logout → clearToken() → user object cleared → useUser() returns { locationId: 0 }
Browser/tab closed → sessionStorage would be lost but localStorage persists; since the token also persists, the user stays logged in and UserProvider rehydrates on next load. To fully clear on browser close you'd need sessionStorage, but then rehydration on a reopened tab would fail — localStorage was chosen to match the token's existing persistence behaviour (the token uses localStorage too).

The user-session interface is defined in src/app/api/auth.ts:10-20:

export interface UserSession {
  id: string
  userName: string
  firstName: string
  lastName: string
  isActive: boolean
  locationId: number
  locationName: string
  email: string
  roles: string[]
}  


How it gets populated at login:
-----------------------------------
The login flow is in the same file (auth.ts:117-187):

login() POSTs to /Authentication/Login and stores the JWT in localStorage under NEXT_AUTH_TOKEN.
It then calls fetchUserSession() (auth.ts:82-115), which GETs /api/ApplicationUser/getbyusername/{username}, maps the response into a UserSession, and persists it to localStorage under NEXT_AUTH_USER_SESSION via setUserSession().
So after login, the full user object (id, locationId, roles, etc.) is sitting in localStorage.


Two ways to retrieve it in a form
1. Directly from the auth helper (what your refund form already does for the username):


import { getUserSession } from '@/app/api/auth'

const user = getUserSession()
user?.locationId   // number
user?.userName     // string
user?.roles        // string[]
Your current invoice-refund-form/index.tsx:10 imports getUserName and uses it the same way — getUserSession() just returns the whole object.


2. The recommended way — via the UserContext (already mounted in the dashboard layout at (DashboardLayout)/layout.tsx:39):


import { useUser } from '@/app/context/UserContext'

// inside a component rendered under the dashboard layout:
const { user, loading, locationId } = useUser()
This rehydrates from localStorage on mount, stays in sync across tabs via a storage listener, and gives you reactive access — so if you want the form to react to login/logout, this beats a one-shot getUserSession() call.



Concrete usage in a react-hook-form form
A typical pattern, auto-filling a field from the logged-in user and including locationId in the submit payload:


'use client'
import { useEffect } from 'react'
import { useForm } from 'react-hook-form'
import { useUser } from '@/app/context/UserContext'
import { postFetcher } from '@/app/api/globalFetcher'

export function MyForm() {
  const { user, loading, locationId } = useUser()
  const { register, reset, handleSubmit } = useForm({
    defaultValues: { preparedBy: '', note: '' },
  })

  // Once the session is hydrated, seed the field.
  useEffect(() => {
    if (!loading && user) {
      reset({ preparedBy: `${user.firstName} ${user.lastName}`.trim() || user.userName })
    }
  }, [loading, user, reset])

  const onSubmit = async (values) => {
    // locationId comes from the session, not the form input
    await postFetcher('/api/Something', {
      ...values,
      locationId,        // ← from useUser(), guaranteed present when authenticated
      preparedById: user?.id,
    })
  }

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('preparedBy')} />
      <input {...register('note')} />
      <button type='submit'>Save</button>
    </form>
  )
}
