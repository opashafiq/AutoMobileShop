agent-guides/transaction-module-guide.md
User enters credentials → auth.login() runs → token stored → fetchUserSession(username, token) runs → user saved to localStorage
Page redirects to dashboard → UserProvider rehydrates from localStorage → useUser() returns user object
Invoice create/edit → useUser() returns locationId → on save, tbim_LocationDetailsId = locationId
Logout → clearToken() → user object cleared → useUser() returns { locationId: 0 }
Browser/tab closed → sessionStorage would be lost but localStorage persists; since the token also persists, the user stays logged in and UserProvider rehydrates on next load. To fully clear on browser close you'd need sessionStorage, but then rehydration on a reopened tab would fail — localStorage was chosen to match the token's existing persistence behaviour (the token uses localStorage too).
